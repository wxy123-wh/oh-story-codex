# 写作规则

## 工作流

- 事件是规划单元，章节是事件内部切片。
- 先生成 `事件库.md`，每卷 4-8 个事件，每个事件覆盖 2-6 章。
- 写正文只读 `写作规则.md`、`全局状态.md`、`事件库.md` 当前事件和上一章正文。
- 事件写完后只更新 `全局状态.md`，不维护多份追踪文件。
- 卷与卷之间依靠 `全局状态.md` 承接。

## 男频章节底层循环

每个事件和章节都要回答：

- 读者现在等什么。
- 本段给读者什么收获。
- 收获前有什么压力、误判、敌人、代价或竞争。
- 主角靠什么行动拿到收获。
- 旁人、敌人、世界规则有什么反应。
- 收获后打开什么新期待。

## 正文级事件素材标准

- 设定要写进现场动作、器物、权力关系、即时利害和对白里。
- 不写抽象提纲句，如“制造冲突”“主角打脸”“埋下伏笔”。
- 正文级素材应能直接扩写成正文，不需要 AI 再把设定翻译成画面。
- 每个事件至少要有关键对白、场景物件、敌人动作、状态改变量。

## 台词差异化

重要角色必须有不同说话系统：

- 句长：短句、长句、断句多、绕弯多、直给。
- 用词：职业、阶层、脾气和教育背景要不同。
- 称呼：怎么称呼主角、上级、敌人、外人。
- 权力姿态：求人、命令、占上风、被逼时说法不同。
- 禁区：这个角色绝不会说什么。

写完后做遮名测试：遮掉角色名，核心角色的对白仍应能分出来。

## 正文禁令

- 正文标题行以外不要出现写作工程词：事件库、全局状态、伏笔、本章、上一章、下一章、读者、细纲、卷纲。
- 少写抽象总结、势力清单、解释腔、排比句。
- 角色行为必须符合当前状态和利益。
- 敌人必须主动行动。
- 每章必须推动事件、人物线或状态变化。
- 章尾只留一个最硬后果或最勾人的动作。
